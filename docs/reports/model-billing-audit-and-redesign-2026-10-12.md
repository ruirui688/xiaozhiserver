# 计费管理审计与改版方案（2026-10-12）

本报告是改版规划，**不是已上线功能说明**。当前实现以[模型管理契约](../models/model-management.md#11-模型用量与实际消费管理)为准。

## 1. 决策结论

把计费管理重新组织为三个日常入口：**费用总览、余额与资源包、用量分析**。账单明细从费用下钻；同步、接入、归属放在管理员设置里。

管理员默认看到供应商账号的官方账单；成员默认看到有权限的工作空间用量。页面始终明确当前范围，标题、金额、表格和状态使用同一范围。查看账号花费不以完成工作空间绑定为前提。

本方案的“管理员”专指平台管理员（`superAdmin`）；工作空间 OWNER/ADMIN 不因此获得平台账号权限，仍只读取获授权空间。

“真实费用”只来自官方账单或可核验的官方账单导入。用量、账户余额、资源包剩余额度分别展示；不按配置单价估价，不按调用比例分摊金额，不把共享账号支出直接认领给某台设备。产品不提供购买、续费、切包或切模型操作。

## 4. 新页面与操作路径

### 4.1 导航及范围

| 页面 | 默认呈现 | 可见筛选 | 次级入口 |
| --- | --- | --- | --- |
| 费用总览 | 管理员：供应商账号、本账期；成员：当前空间可核实费用 | 供应商账号、账期；下钻后产品/服务 | 官方账单、账单来源、归属说明 |
| 余额与资源包 | 当前范围的最新额度快照；资金仅账号管理员可见 | 产品、有效/已耗尽/已到期；音色权益独立折叠 | 适用条件、官方观察记录、抵扣证据 |
| 用量分析 | 当前空间；按智能体、按设备、调用记录是页内视图 | 调用日期、服务；智能体/设备/型号/用途按需展开 | 单次调用、采集状态、覆盖范围 |
| 数据接入与归属（设置） | 仅管理员 | 来源、账号、账期、运行实例 | 同步结果、采集健康、归属预览 |

顶部只保留一个显式范围切换：“供应商账号 / 工作空间”。供应商账号筛选仅在平台账号范围出现，普通成员不出现平台账号选项。账号资金不能出现在工作空间金额卡中；从账号费用跳转“谁在使用”时显式选定空间，再更新整个页面范围，不暗中复用上一个空间。

账单选账期，用量选日期，额度标注快照时间。三个页面各自保存筛选并写入 URL；浏览器返回后恢复范围。账号模式隐藏页面的空间选择器，切到空间模式才展示获授权空间；若全局 Header 仍保留空间切换，明确提示它不影响当前账号账务范围。空间显示可读名称，ID 只在详情中出现。

### 4.2 管理员进入后，先能读懂钱

首屏先列供应商，不展示看似完整的“全部模型总消费”：

- 火山引擎：显示本期已同步官方账单的应付、已付及未付，各自有口径说明和最后成功时间；当前示例主金额可展示“官方已付 ¥36.29”。
- DeepSeek：当前实际消费标“尚无官方消费账单”，进入官方导入或来源说明；“余额 ¥98.94”放在余额区。
- 缺失来源明确标注覆盖不完整，不能以火山金额代替两家供应商总支出。
- 下方按供应商官方产品分类，展示“语音合成 / SeedTTS 2.0”等已验证映射。未知产品保留官方名称，不强行塞入 LLM/ASR/TTS。
- 账单明细展示账期、产品、原始计费方式、官方金额、官方抵扣量、归属状态；先看到主账单，展开其明细，不给用户两层金额相加的机会。

`PaidAmount` 首版命名为“官方已付金额”，含义为所选账期账单截至快照的官方已付，不能称为本月支付流水或净现金流。只有官方字段定义和支付构成已核实，才使用“现金支付”等更具体名称；不能把它默认解释为完整经济消费成本。

### 4.3 查看谁在使用

路径：**用量分析 → 工作空间 → 按智能体 / 按设备 → 调用记录**。智能体和设备是同一批调用的两个维度，不把设备固定为智能体的永久子节点。

- LLM 显示输入/输出 Token 和缓存子项；ASR 显示供应商时长；TTS 按官方字符、Token 或时长；不同单位不求和。
- 设备分类包含设备型号，并可查看一台设备切换不同智能体后的历史；调用发生时的归属不随当前绑定改变。
- 后台任务、评测等用途单列，避免用户看到设备调用之和小于空间总量却无解释。
- 实际金额只有取得对应粒度的官方证据才显示；否则写“供应商账单不能细分到此设备”，用量仍可查看。
- Realtime 单列，不虚构拆成 ASR、LLM、TTS 三次消费；设备端语音与本地缓存命中不制造云端调用。
- 只有完整覆盖所选时间、服务且无采集中断，才能将零事件解释为该范围零使用；否则显示“已采集 0 条，覆盖尚不完整”。首次无证据显示“尚未收到用量记录 · 采集接通待验证”。供应商没返回某指标显示“未提供”，不是 0。

## 5. 资源包如何变得有用

### 5.1 三种东西分开

1. **账户资金**：DeepSeek 充值余额、赠送余额等；不能由余额差推算真实消费。
2. **可抵扣额度**：字符、小时、Token 等；显示官方剩余值、有效期、产品及共享条件，已耗尽/过期归档但可查。
3. **音色与功能权益**：使用许可、并发等；没有字符余额是“不适用”，不应显示为欠缺额度的数据行。

同一购买实例的通用接口与语音接口记录合并为一个详情中的两条“官方来源”。合并必须验证同一账号和稳定实例；保留来源时间、单位、周期、项目及查询覆盖。免费包无稳定实例时保持独立观察，不用产品 ID 或列表序号冒充唯一资产 ID。

当前值得展示的待核实项包括：通用接口中 ASR 2.0 的两个 30 小时包仍各余 30 小时；BigTTS 有未用完额度，SeedTTS 2.0 的已查询字符额度耗尽。它们是不同产品的观察结果，**不能默认互相抵扣**。另一个通用 BigTTS 包未出现在当前语音项目查询中，需核对其项目、适用产品和查询覆盖，不能直接称为失效包。

### 5.2 “有包还扣费”诊断卡

每条提示包括“已知事实、尚缺证据、下一步”，状态只有“已确认抵扣 / 已确认不适用 / 待核实”，避免模糊的“异常”标签。

| 核对顺序 | 所需官方或运行证据 | 缺证据时的展示 |
| --- | --- | --- |
| 是否同一个产品 | 调用的官方产品/模型、计费 ResourceID、包适用产品的已核验映射 | 产品匹配待确认；推理模型名不能直接替代计费产品 ID |
| 是否同账号及适用项目 | 账号、项目/App、是否共享、调用凭据的安全引用 | 项目适用范围待确认；不展示密钥 |
| 当时包是否有效 | 消费时间、包生效/到期、当时额度、重置周期 | 当前余额不能证明消费发生时有额度 |
| 计量是否符合 | 流式/录音等产品模式、计量单位、区域和官方适用限制（如有） | 模式或单位不明，不判定可抵扣 |
| 实际扣了什么 | 官方明细中的抵扣记录、包实例及关联账单，或官方可导出的抵扣凭证 | 尚未取得该笔费用的包抵扣证据 |

不因为有余额且有账单就认定多扣钱，也不因为账单金额 0 就认定资源包已抵扣；可能存在免费额度、赠送或其他优惠，必须显示官方依据。

### 5.3 后续智能管理的边界

- 先支持可信的临期、额度耗尽、数据过期和待核实提示；来源失败时保留最后成功快照并明显标记。
- 在官方字段能力验证后保留历史观察，识别长期未消耗、接近到期仍有余量等趋势；不把当前单次快照称为长期闲置证据。
- “哪个包划算”要有实际购买金额、适用产品、有效期、已确认抵扣量、退款和到期剩余。仅对同一购买实例、同单位且已确认使用量大于零，计算“扣除已确认退款后的实际支付 / 已确认使用额度”，同时注明未到期与未完全使用会影响结果；不存在可比官方按量消费证据时，不给出节省金额。
- 若未来展示耗尽时间预测，应独立标“基于历史用量的预测”，不能进入实际费用账本，也不能触发自动购买或模型切换。

## 6. 后端契约与采集规划

### 6.1 账号总账与权限

建议接口名为设计占位，不表示已经实现：

| 拟定读接口 | 关键参数/返回 | 权限与边界 |
| --- | --- | --- |
| `GET /billing/account-overview` | provider、accountRef、billPeriod；按币种返回主账单应付/已付/未付、覆盖范围、对账状态 | 仅平台管理员；不依赖当前 workspace 绑定；不是未归属账单汇总 |
| `GET /billing/account-bills` | 账号全量主账单分页；产品、账单号、账期；按父单下钻明细 | 服务端强制管理权限；未知账号拒绝；保留原始层级 |
| `GET /billing/sync-status` | 每个来源/账号/账期的最近尝试状态、成功时间、是否有快照、是否过期 | 成员只接收本空间可见状态，不泄漏平台金额或数量 |
| 现有空间用量及费用接口 | scope、workspaceName、coverage、supportedFilters、金额不可细分原因 | 使用已有空间权限；不能信任请求体中的空间/设备归属 |
| 权益读接口升级 | assets、sourceObservations、coverage、lastSuccessAt、lastAttemptStatus | 账户资金仅管理员；共享权益不能因选中空间就认领 |
| `GET /billing/collection-health` | 实例/服务覆盖、采集起点、投递/积压/拒绝状态 | 管理员看实例排障；成员看脱敏的空间采集情况 |

所有金额使用十进制字符串及币种，不进行前端浮点累加或隐式汇率转换。官方修订、退款、资源包购买及按量消费按有依据的类别展示；包购买是付款交易，后续抵扣量不能再次加成付款。原始凭证与去重键保留，账户归属规则变化不改变账号总账。

API 保留账单币种 `Currency`、结算币种 `CurrencySettlement` 与 `paymentCurrencyVerified`。跨币种已付字段口径未核实时，不把已付金额直接按账单币种归并；延续现有查询对币种不一致的保护。

每个主账单增加独立的对账读状态：分页完成、明细数量、同币种金额核对、差额、观察时间。孤立明细、跨币种或主明细不一致显示待核对，不静默合入“已核实总额”。没有账单行时，仅在成功同步且覆盖该账号账期的前提下显示零账单；否则是未取得。

优先复用当前账单和凭证数据。同步任务缺少账号字段，需新增 Liquibase 迁移及索引，历史无法确定账号的任务标记为未知，不能猜测回填。健康信号和历史观察按已验证数据契约另做最小迁移；不预先构建庞大资产交易系统，不修改任何已发布迁移。

### 6.2 采集健康

Python 上报脱敏运行状态：实例版本、配置托管模式、支持的 adapter、上下文接收情况、最近调用、最近成功投递、active/pending/rejected 数量和持久化失败。Java 分别报告接收/入库状态和自己的队列；不把两条链路合成一个 READY。

| 情况 | 用户文案 |
| --- | --- |
| 无心跳或未取得计量上下文 | 采集接通待验证 / 配置上下文缺失 |
| 心跳和配置正常，尚无事件入库 | 状态上报正常，等待首条用量验证；分别呈现心跳、上下文和入库状态 |
| 有调用，SQLite 队列有待投递事件 | 用量待补传，数字可能不完整 |
| 有拒绝或磁盘持久化失败 | 部分用量未入账，查看原因 |
| 心跳正常但设备闲置 | 当前时段没有新调用，不报采集故障 |
| 当前 adapter 尚未接入 | 此模型暂未采集，不能显示为已完整覆盖 |

分别记录 `enabledAt / firstContextAt / firstEventAt` 和中断区间。第一条事件只证明第一条已采集，不能声称此前覆盖完整。当前覆盖集中在 OpenAI 兼容调用、豆包流式/录音 ASR、火山双流 TTS 和已接入 Realtime adapter，其他 provider 必须逐项审查。

## 7. 实施顺序和多智能体分工

| 阶段 | 交付内容 | 主要路径和责任 | 完成门槛 |
| --- | --- | --- | --- |
| P0 可信状态与口径 | 账号账期数据契约、主明细核对、采集健康、证据不足状态 | API agent：`main/manager-api/`；采集 agent：`main/xiaozhi-server/`；集成者评审合同 | 不出现假零、假就绪、重复金额；范围与权限测试通过 |
| P1 日常页面改版 | 三入口；管理员账号首屏；费用下钻；资源包去重与权益分类；空间/智能体/设备用量 | Web agent：`main/manager-web/`；API agent 提供读模型 | 用户无需说明即可走通三条任务路径；所有可见筛选有效 |
| P2 抵扣诊断 | 产品适用矩阵、官方抵扣证据能力验证、历史观察、只读诊断 | API agent 主导；采集 agent 补足安全引用；Web agent 展示 | 同产品、账号、时间、单位证据可追溯；未知仍是未知 |

界面拆为总览、账单、权益、用量和状态组件，页面壳只编排范围与路由；不要继续把业务堆入一个大 Vue 文件。Java 账号聚合与空间查询分服务，Python 健康报告放入计量模块，避免扩张 `connection.py`。

集成者维护契约和验收矩阵，检查关键 diff、权限、脱敏及新迁移。子智能体仅修改各自路径，跨边界需求先交接。改版保留已有账单、凭证、幂等键和调用归属快照，不通过删除重建数据“修好首页”。

## 8. 验收清单

| 场景 | 必须成立 |

| 管理员，无任何归属绑定 | 能直接看到账号全量账期费用；给本批样本应得官方已付 36.29，而非空白或 72.58 |

| 空账期成功同步、最新同步失败 | 前者显示成功时间及零账单；后者显示失败并保留最后成功快照 |
| 账期含跨月/无结束时间预付单 | 账号账期页可查；空间归属仍需完整独占证据，不按天摊费用 |
| 一个包出现在两个来源 | 展示一个经确认的购买实例，含两个来源；金额/额度不重复累加 |
| 213 条音色权益 | 不占用默认可抵扣包列表，不参与字符余额或包数量汇总 |
| 有包且有非零账单，缺抵扣关联 | 显示待核实及缺失证据；不声称多扣费，不提供切换操作 |
| 无心跳、配置失败、旧 API 不返回上下文 | 页面不能显示采集正常或完整的零使用 |
| 日期跨越采集启用日或包含未接入 adapter | 标注覆盖不足，不能把已采集零条解释成整个期间零使用 |
| 网络故障、拒绝、确认丢失后重传 | 显示待补传/拒绝，恢复后幂等入库；闲置但心跳正常不误报警 |
| 设备从智能体 A 切到 B 后补传 | A 的历史仍归 A；设备汇总可跨 A/B；智能体与设备两种汇总不能再次相加 |
| 普通语音、工具续轮、打断、Realtime、设备端语音 | 对照覆盖合同记录真实上游调用；未知用量不补零，不虚构额外 ASR/TTS |
| 页面操作 | 账号花费、资源包详情、空间到设备用量各不超过三次主要跳转；刷新/返回保持范围，320px 和桌面无溢出 |
