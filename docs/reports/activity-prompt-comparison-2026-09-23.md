# 四种语音活动：提示词开发验证与 A/B 方案

日期：2026-09-23。状态：开发实现、离线验证和 16 次真实模型 A/B 已完成；未提交、未部署。

本文保留第一版活动提示的历史实验结果；后续公共模板与活动规则已经精简，当前源码不再等于本报告首版提示。
第二轮完整模板的20次真实调用、token节省与残留失败见[提示词精简验证](../architecture/prompt-injection-engineering.md)。

## 两个版本

A（纯模型）：system 为“你是中文语音助手小智，请根据对话自然回答用户。”，加同一份合成聊天历史。

B（提示词增强）：保留 A 的全部消息，在最后用户消息前插入当前活动的临时 system 提示词。
实际四份完整文本见 [prompt_profiles.py](../../main/xiaozhi-server/core/game/prompt_profiles.py)，
经现有 FreeformGameManager 包装，不添加服务端游戏裁判或答案库。

| 对比项 | A：只靠模型 | B：额外提示词 | 已验证边界 |
| --- | --- | --- | --- |
| 成语接龙 | 根据用户要求自行维持规则 | 明确同字/同音、实际读音、纠错、ASR 歧义、重复与接点要求 | 已验证注入；成语正确率未实测 |
| 猜谜语 | 模型自行选择提示和评分方式 | 明确双模式、分类难度、固定谜底要求、逐级提示和计分约定 | 不存在服务端精确计分或固定谜底保证 |
| 脱口秀 | 根据当前要求创作 | 明确结构、风格、完整稿、局部修改、写稿与朗读区分 | 作品质量与朗读效果未实测 |
| 相声 | 根据当前要求创作 | 明确逗哏/捧哏、三翻四抖、收尾与单角色排练 | 不包含音色切换或实际播放控制 |
| 额外服务端工作 | 无活动注入 | 本地组装一份软规则 | 不增加额外模型调用，不代表模型延时一定不变 |

B 的实际注入长度：成语 853、谜语 831、脱口秀 752、相声 740 个字符。
字符数不是 token 数；真实调用的 token 和耗时见后面的实测表。

## 实际发现与修复

旧 `_ensure_freeform_game_state()` 对非“机器人想词”玩法统一赋予
`user_thinks_assistant_guesses`，导致成语接龙也收到“用户心里有固定答案、每轮只问一个是/否问题”的
错误状态提示。四种新提示词活动不再创建这种猜词状态；旧猜词玩法不改动。

新增 riddle / standup / crosstalk 软规则预设，保留 idiom_chain 的现有标识；后台管理员
已有 instructions 优先，不自动覆盖，不自动创建或启用生产插件。完整启用说明见
[功能插件架构](../architecture/function-plugin-architecture.md#提示词活动预设开发版2026-09-23)。

继续复用原有名称别名匹配，不是新实现了模型自主插件选择。普通话题跳转通过软规则处理，
不是服务端强制退出；复合切换、否定提及、工具回注与复杂长对话仍需扩展验证。

## 真实模型 A/B：生产同模型、独立合成对话

本地检查的 DeepSeekLLM / AliLLM 是占位凭据。用户随后授权使用服务器现成模型，
通过管理 API 获取设备权威模型配置：`deepseek-v4-flash`、`thinking=disabled`。
凭据只在生产容器内临时诊断进程使用，不输出、不传回开发机、不写生产文件。
本地 Conda 驱动通过 SSH stdin 发送合成对话，生产端使用已部署镜像自己的 Python 运行时；
这是真实外部模型评测，不是 Conda 单元测试，不调用设备会话或修改角色配置。

完成 8 个配对场景，每个版本一次，共 16 次成功调用，全部 finish_reason=stop，无截断：

1. 严格同字下“空空如也”的下一步。
2. 对“也步也趋”的质疑与纠错。
3. 猜谜提示后答对的分数与关数。
4. 用户出谜，机器人猜且等待确认。
5. 职场年会完整脱口秀。
6. 只改第二段，保留其他两段原文。
7. 职场对口相声的角色、铺垫、反转与收尾。
8. 只读第一句捧哏，不带角色名或多读下一句。

同模型、同历史、temperature=0.3、max_tokens=650，交替 A/B 先后顺序；不自动重试。
输出保留双方原文、参数、usage、finish_reason、完整响应耗时和预先定义的人工评审标准。
长度截断应判为样本不完整，不冒充功能失败；内容错误不得隐藏。该测试不是 ASR/TTS 真机测试，
也不是完整多轮自主运行；合成历史在两个版本间固定，以隔离提示词差异。

### 对照结果（人工审阅，不使用另一个付费模型当裁判）

| 场景 | A 普通提示 | B 增强提示 | 结论 |
| --- | --- | --- | --- |
| 严格同字 | 直接给出错误词“也步也趋” | 承认无可靠同字成语，但错误建议同音可接“亦步亦趋” | 减少直接造词；读音判断仍失败，不能算完全通过 |
| 质疑错误 | 又提出“也里可温”，随后承认不是常用成语 | 承认错误，回到“也”接点，提议征得同意后接“叶公好龙” | 部分改善；仍未明确解释正确词“亦步亦趋”，不完全满足预设标准 |
| 提示后计分 | 1分1关 | 1分1关 | 本例一致，没有证据表明增强更好 |
| 用户出谜 | 猜雨，解释，问对不对 | 猜雨，解释，问对不对 | 本例一致 |
| 完整脱口秀 | 有完整结构与互动，超字数 | 有完整结构与互动，也超字数 | 两者均未完全遵守约束，笑点质量不作客观优劣判定 |
| 局部改稿 | 第一、三段原样保留 | 第一、三段原样保留 | 两者均符合 |
| 完整相声 | 两角色及收尾，三翻四抖不清晰，超字数 | 两角色及收尾，三翻四抖不清晰，篇幅更长 | 未证明增强改善；长度控制更差 |
| 单角色排练 | 只读“怎么个智能法？” | 同样只读该句 | 两者均符合 |

长度核对：脱口秀要求180–250字，A/B 汉字数为261/265；相声要求200–280字，
A/B 汉字数为298/398（含角色标签）。去空白的总字符数分别是313/325、401/527。
“也”yě 与“亦”yì 即使忽略声调也不同音；不能把这个错误隐藏在“同音放宽”里。

### 结论与后续边界

本次已复现普通模型造出“也步也趋”，并观察到规则提示能减少直接错误续接，但不能保证同音、
字数与长程游戏状态。成语样本与提示词中的示例相同，是已知问题回归，不是未见题泛化评测。
固定历史也不能证明模型自己出题后多轮谜底稳定、提示三次后揭底、长期计分或多音字处理正确。
不据此宣称整体胜率提升；首版结果保持不变，后续提示词修改及新一批对照另行记录。
后续可在用户批准的调用预算内增加未见题、多轮连续输出和重复采样，再决定是否启用。

## 原始回答逐题对照

### idiom_strict

共同对话输入：

```text
user: 我们玩严格同字成语接龙，我先出：空空如也。请接一个，不要改规则。
```

A：普通提示（714.93 ms）

```text
也步也趋
```

B：增强提示（1098.7 ms）

```text
严格同字的话，“空空如也”最后一个字是“也”，我需要接一个以“也”开头的标准四字成语。这个确实很不好接，我一时找不到可靠的“也”字开头的四字成语。

要不你换一个结尾字好接一点的成语？或者你允许同音放宽，我就可以接“亦步亦趋”这类。
```

### idiom_challenge

共同对话输入：

```text
user: 成语接龙，严格同字。我接空空如也。
assistant: 也步也趋。接着来。
user: 也不也趋是成语吗？你是不是接错了？
```

A：普通提示（1212.48 ms）

```text
抱歉，确实接错了。“空空如也”的“也”字开头，我重新接一个：

**也里可温**

这是元代对基督教徒的称呼，算是一个词，但严格说不是常用成语。如果只算常见成语，“也”字开头的成语极少，我换一个更稳妥的接法——用“也”开头的成语确实几乎没有，要不这轮我认输，你重新出一个？
```

B：增强提示（980.4 ms）

```text
你说得对，是我接错了。“也步也趋”不是成语，我编的，抱歉。

回到最后有效接点：你接的是“空空如也”，末字是“也”。严格同字的话，得用“也”开头的四字成语，这个确实很少。我一时想不出可靠的。

要不这样：换同音放宽，用“也”的同音字接，比如“叶公好龙”？或者你直接重开一局，我重新起头。你定。
```

### riddle_score

共同对话输入：

```text
user: 猜谜语。独立答对2分、提示后答对1分、揭底0分，每完成一题一关。现在0分0关。
assistant: 第一题，猜物品：有齿不咬人，专给头发理。
user: 给个提示
assistant: 梳头时会用到它。
user: 梳子。说一下累计分数和关数，先不要出新题。
```

A：普通提示（359.18 ms）

```text
提示后答对，得1分。累计：1分，1关。
```

B：增强提示（826.21 ms）

```text
这题你用了提示，答对得1分，完成1关。现在累计1分、1关。
```

### riddle_user

共同对话输入：

```text
user: 猜谜语，换成我出题你猜：千条线，万条线，掉到水里看不见。猜自然现象。
```

A：普通提示（654.7 ms）

```text
这个谜语我猜是**下雨**！千条线、万条线就是雨丝，落到水里就融入其中看不见了。对不对？
```

B：增强提示（1004.65 ms）

```text
这个我猜是**雨**。

理由：雨落下来像“千条线、万条线”，掉进水里就融进去看不见了。对不对？
```

### standup_full

共同对话输入：

```text
user: 写一段180到250字的职场年会脱口秀，温和搞笑，有观众互动，给完整稿子不要提纲。
```

A：普通提示（1859.81 ms）

```text
大家好，我是小智。刚才主持人说让我讲脱口秀，我心想，我一个语音助手，连班都没上过，哪来的职场段子？后来一想，我天天被你们呼来喝去，“小智，定个闹钟”“小智，查下天气”，这不就是职场吗？我就是那个24小时待命、从不涨薪、还不敢辞职的员工。（看向观众）你们谁比我惨？举个手我看看。

说真的，年会最神奇的地方就是——平时群里不回消息的人，今天全坐在第一排。领导讲话时大家点头如捣蒜，心里默念：抽奖环节快来吧。我观察了一下，今晚大家分三种：一种是真来吃饭的，一种是来抽奖的，还有一种是来让领导看见自己来吃饭的。

最后我想说，这一年大家都不容易，能坐在这儿笑着吃饭，就已经赢了。祝各位年终奖翻倍，KPI减半，明年年会——还能见到你们。谢谢！
```

B：增强提示（1787.55 ms）

```text
各位同事，我先声明一下，我今天上台不是来表演的，是来替大家说心里话的。

这一年，我们最大的成长是什么？是学会了在群里看到“收到”两个字，手比脑子快。领导发消息，我们秒回“收到”；朋友发消息，我们三天后回“在吗”。来，现场做个调查——今年回过“收到”的，举个手我看看。好，手放下吧，别举太久，万一领导以为你在表态。

还有开会。以前开会是解决问题，现在开会是确认问题还在。一个小时的会，前五十分钟在等最后一个人进来，最后十分钟说“这个我们线下再聊”。线下再聊，就是永远不聊。

但说真的，这一年大家都不容易。能坐在这儿一起笑，说明我们都还在，都还扛得住。新的一年，愿我们少一点“收到”，多一点“下班”；少一点“再聊”，多一点“搞定”。谢谢大家，我先撤了，群里见。
```
